# スタイルルール仕様

> Google Java Style Guide をベースとし、以下の 4 点を独自に改変する。

## 改変事項一覧

| # | 改変事項 | Google Style Guide 規定 | 本プロジェクトの規定 | 分類 |
|---|---|---|---|---|
| 1 | インデント幅 | 2-space | **4-space (AOSP)** | 規定値の変更 |
| 2 | ファイル末尾の改行 | 未規定 | **必須** | 規定の追加 |
| 3 | 行末の空白 | 未規定 | **不許可** | 規定の追加 |
| 4 | ファイルヘッダ | 組織ポリシーに委任 (Section 2.1) | **`// fuj1g0n demo, love coding` を必須** | 規定の追加 |

---

## 改変 #1: インデント幅 (2-space → 4-space)

| 項目 | Google Style Guide | 本プロジェクト |
|---|---|---|
| ブロックインデント (Section 3.2) | +2 | **+4** |
| 継続行インデント (Section 3.5) | +4 | **+8** (比率 2 倍を維持) |
| switch case (Section 3.8.4.1) | +2 | **+4** |

**根拠**:
- Java エコシステムでは 4-space が主流 (Spring Boot/Framework も 4-space)
- google-java-format の `AOSP` スタイルが完全対応し、カスタムフォーマッタ不要
- AOSP はインデント幅以外 (ブレース配置、空白、import 順序等) を Google Style と同一に保つ

**列制限**: 100 文字を据え置き。4-space 化後の違反頻度を実測し、必要に応じて 120 への拡張を検討する。

---

## 改変 #2: ファイル末尾の改行を必須

**根拠**:
- POSIX 標準ではテキストファイルは改行で終端する
- `git diff` で `\ No newline at end of file` 警告が diff ノイズになる
- google-java-format 自体が暗黙的に改行を自動付与しており、事実上の標準動作
- Java 以外のファイル (`.xml`, `.yml` 等) にも統一適用する

---

## 改変 #3: 行末の空白を不許可

**根拠**:
- 可視的に意味がなく、エディタの設定差異で追加・削除が繰り返され、無意味な diff ノイズの原因になる
- 多くの規約 (Linux kernel, PEP 8 等) で明示的に禁止
- google-java-format が暗黙的に自動除去しており、事実上の標準動作
- Java 以外のファイルにも統一適用する

---

## 改変 #4: ファイルヘッダの必須化

全 Java ファイルの先頭に `// fuj1g0n demo, love coding` を必須とする。

**根拠**:
- プロジェクトのアイデンティティを各ソースファイルに明示する
- Section 2.1 はヘッダの内容・有無を組織ポリシーに委ねており、Style Guide に矛盾しない

**IDE への影響**: google-java-format プラグイン (方式 A) ではヘッダが挿入されないため、Spotless 呼び出し (方式 B) の価値が高まる。
