# 「この数字、なんの数字？」クイズアプリ — 要件定義

> **ステータス**: Draft
> **最終更新**: 2026-03-03

## 1. プロダクト概要

### 1.1 コンセプト

「1,718兆円」「47」「0.03%」—— 金融・行政の世界には、知っているようで正確には答えられない数字が溢れている。
本アプリは、こうした数字を **4択クイズ** として出題し、回答者の「数字感覚」を測定・可視化する Web アプリケーションである。

### 1.2 ターゲットユーザ

| ユーザ | 利用シーン |
|---|---|
| デモ参加者（金融機関・公共機関の担当者） | デモ会場でライブ体験。Spring Boot アプリの動作イメージを掴む |
| 社内エンジニア | ハンズオン教材として、コードの構造・設計パターンを学ぶ |

### 1.3 設計方針

- **デモファースト**: 初回起動から 30 秒以内にクイズを体験できること
- **シンプル**: 認証なし・最小限の画面遷移で動作すること
- **教材価値**: Spring Boot の典型的な設計パターン (Controller → Service → Repository) を示すこと
- **面白さ**: 出題内容が知的好奇心を刺激し、結果画面で「へぇ〜」と思える解説を表示すること

## 3. 画面構成

### 3.1 画面一覧

| # | 画面名 | パス | 概要 |
|---|---|---|---|
| S-01 | トップページ | `/` | アプリ紹介＋「クイズを始める」ボタン |
| S-02 | クイズ出題画面 | `/quiz/play` | 数字の表示＋4択選択肢 |
| S-03 | 回答結果画面 | `/quiz/answer` | 正解/不正解＋解説表示＋「次の問題へ」ボタン |
| S-04 | 最終結果画面 | `/quiz/result` | スコア＋称号＋「もう一度」ボタン |
| S-05 | 管理：問題一覧 | `/admin/questions` | 問題の一覧表示 (テーブル) |
| S-06 | 管理：問題登録/編集 | `/admin/questions/new`, `/admin/questions/{id}/edit` | 問題の入力フォーム |

### 3.2 画面遷移フロー

```
[S-01 トップ] → [S-02 出題] → [S-03 回答結果] → [S-02 出題 (次の問題)]
                                                   ↓ (最終問題の場合)
                                               [S-04 最終結果] → [S-01 トップ]
```

## 4. データモデル

### 4.1 エンティティ

#### Question (クイズ問題)

| フィールド | 型 | 制約 | 説明 |
|---|---|---|---|
| `id` | `Long` | PK, Auto | 問題 ID |
| `numberValue` | `String` | Not Null | 出題する数字 (例: `"1,718兆円"`, `"47"`, `"0.03%"`) |
| `correctAnswer` | `String` | Not Null | 正解の説明 (例: `"日本の家計金融資産"`) |
| `wrongAnswer1` | `String` | Not Null | 不正解の選択肢 1 |
| `wrongAnswer2` | `String` | Not Null | 不正解の選択肢 2 |
| `wrongAnswer3` | `String` | Not Null | 不正解の選択肢 3 |
| `explanation` | `String` (Text) | Not Null | 正解発表時に表示する解説文 |
| `category` | `String` | Not Null | カテゴリ (`FINANCE`, `PUBLIC_SECTOR`, `GENERAL`) |
| `difficulty` | `Integer` | Not Null, 1-3 | 難易度 (1: 易, 2: 普通, 3: 難) |
| `createdAt` | `LocalDateTime` | Not Null | 作成日時 |
| `updatedAt` | `LocalDateTime` | Not Null | 更新日時 |

#### QuizAttempt (回答履歴)

| フィールド | 型 | 制約 | 説明 |
|---|---|---|---|
| `id` | `Long` | PK, Auto | 回答履歴 ID |
| `sessionId` | `String` | Not Null | ブラウザセッション識別子 |
| `questionId` | `Long` | FK → Question | 回答した問題 |
| `selectedAnswer` | `String` | Not Null | プレイヤーが選んだ選択肢 |
| `isCorrect` | `Boolean` | Not Null | 正解したか |
| `answeredAt` | `LocalDateTime` | Not Null | 回答日時 |

### 4.2 設計上の判断

| 判断ポイント | 決定 | 理由 |
|---|---|---|
| 選択肢の持ち方 | Question テーブルに直接 4 カラムで保持 | デモアプリとしてシンプルさを優先。正規化 (Choice テーブル分離) は過剰 |
| ユーザ管理 | セッションベース (認証なし) | デモで即体験できることを最優先。ログイン画面は不要 |
| 出題数 | 1 回のプレイで 10 問 (定数) | デモの時間内に完了する適切なボリューム |
| 選択肢の表示順序 | 回答ごとにシャッフル | 正解の位置を固定しないことで公平性を担保 |

## 6. クイズ問題サンプル (初期データ)

デモの面白さを担保するために、以下のバランスで初期データを投入する。

### 6.1 カテゴリ別配分

| カテゴリ | 問題数 | 例 |
|---|---|---|
| 金融 (FINANCE) | 5 問 | 家計金融資産、日銀の金利、NISA 口座数 etc. |
| 行政 (PUBLIC_SECTOR) | 3 問 | 国家予算、公務員数、マイナンバーカード普及率 etc. |
| 一般常識 (GENERAL) | 2 問 | 日本の人口、平均寿命 etc. |

### 6.2 問題サンプル

#### サンプル 1 — 金融

- **数字**: `2,141兆円`
- **正解**: 日本の家計金融資産 (2024年末時点)
- **不正解1**: 日本の GDP
- **不正解2**: 日本の国債残高
- **不正解3**: 世界の仮想通貨の時価総額
- **解説**: 日本銀行「資金循環統計」によると、2024年末時点の日本の家計金融資産は約2,141兆円。その半分以上が現金・預金で占められており、「貯蓄大国ニッポン」の姿が浮かび上がります。

#### サンプル 2 — 行政

- **数字**: `115兆円`
- **正解**: 令和7年度 一般会計予算 (当初予算)
- **不正解1**: 日本の防衛費 (5年間合計)
- **不正解2**: 地方交付税交付金の総額
- **不正解3**: 社会保障給付費
- **解説**: 令和7年度の一般会計予算は約115兆5,415億円で過去最大を更新。社会保障費が最大の歳出項目で、全体の約3分の1を占めています。

#### サンプル 3 — 一般常識

- **数字**: `47`
- **正解**: 日本の都道府県の数
- **不正解1**: 日本の政令指定都市の数
- **不正解2**: 衆議院の比例ブロック数
- **不正解3**: 国連安保理の理事国数
- **解説**: 意外とシンプルな問題ですが、デモの場で「え、47 って何だっけ？」と一瞬考える人は多いものです。1972年の沖縄返還以来、47都道府県の体制が続いています。

### 7.2 パッケージ構成

プロジェクトの指示ファイルに従い、機能/ドメイン単位で構成する:

```
com.example.numberquiz
├── quiz/                         # クイズ回答機能
│   ├── QuizController.java       # クイズ画面の表示・回答処理
│   ├── QuizService.java          # 出題ロジック・スコア計算
│   ├── QuizSession.java          # セッション内のクイズ状態管理
│   └── QuizResult.java           # 結果表示用 Record
├── question/                     # 問題管理機能
│   ├── Question.java             # エンティティ
│   ├── QuestionRepository.java   # Spring Data JPA リポジトリ
│   ├── QuestionService.java      # 問題の CRUD ロジック
│   ├── QuestionController.java   # 管理画面の Controller
│   ├── QuestionForm.java         # フォーム入力用 Record
│   └── Category.java             # カテゴリ enum
├── attempt/                      # 回答履歴機能
│   ├── QuizAttempt.java          # エンティティ
│   ├── QuizAttemptRepository.java
│   └── QuizAttemptService.java
└── config/                       # 設定
    └── AppConfig.java
```

### 7.3 設計原則 (プロジェクト規約からの適用)

- **Controller は薄く**: リクエストの受付とレスポンスの返却のみ。ロジックは Service に委譲
- **コンストラクタインジェクション**: `@Autowired` フィールドインジェクションは使用しない
- **Record の活用**: DTO (フォーム入力、結果表示) には Java Record を使用
- **不変性**: 定数には `List.of()` / `Map.of()`、ローカル変数は `var` を使用
- **Null 安全**: 戻り値には `Optional<T>` を使用し、`null` を返さない

## 8. 非機能要件

| 項目 | 要件 |
|---|---|
| レスポンス | 全画面 1 秒以内に描画 (ローカル環境) |
| 同時接続 | デモ用途のため 10 名程度が同時利用可能であれば十分 |
| データ永続性 | ローカル環境では H2 インメモリのため再起動でデータリセット (意図的) |
| ブラウザ対応 | Chrome 最新版で動作確認。他ブラウザはベストエフォート |
| アクセシビリティ | Bootstrap のデフォルトに準拠 (追加対応は行わない) |
| セキュリティ | 認証なし。管理画面も認証不要 (デモアプリのため) |
| 国際化 | 日本語のみ |

## 9. テスト方針

### 9.1 テストレベル

| レベル | 対象 | ツール | 優先度 |
|---|---|---|---|
| 単体テスト | Service 層のロジック (スコア計算、出題ロジック) | JUnit 5 + Mockito | Must |
| Repository テスト | JPA クエリの検証 | `@DataJpaTest` + H2 | Must |
| Controller テスト | 画面遷移・フォーム処理 | `@WebMvcTest` | Should |
| 統合テスト | 一連のクイズフロー | `@SpringBootTest` | Should |
| E2E テスト | 画面表示・クリック操作 | Playwright | Could |

### 9.2 重点テストケース

- **出題ロジック**: ランダム出題で全問異なることの検証
- **選択肢シャッフル**: 正解の位置がランダムであることの検証
- **スコア計算**: 0 点 / 満点 / 境界値での称号判定
- **問題 CRUD**: 登録 → 一覧表示 → 編集 → 削除の一連フロー
- **セッション管理**: 複数ブラウザで独立してクイズが進行すること
