# 手動テスト計画（Gherkin 形式）

## 手動テストの位置づけ

手動テストは、Unit Test / Integration Test / System Test の自動テストで
**カバーできない領域**（視覚的確認、UX、レイアウト崩れ等）のみを対象とする。

## 要否判断の基準

1. 対象のユーザーストーリー・実装内容を分析する
2. 自動テスト 3 レベル（`testing-strategy` skill 参照）でカバー可能かを判断する:
   - カバー可能な場合: 「手動テストは確認の上不要と判断しました。理由: <理由>」と明記する
   - カバーできない領域がある場合: 手動テストカテゴリのサブタスクを作成する
   - 判断がつかない場合: ユーザーに質問する

## テストケースの記述形式

テストケースは必ず **Gherkin 形式**（Feature / Scenario / Given / When / Then）で記述する。

```gherkin
Feature: クイズ一覧画面の視覚的確認

  Scenario: モバイル表示でレイアウトが崩れない
    Given アプリケーションが起動している
    When iPhone 15 相当のビューポートで一覧画面を表示する
    Then クイズカードが縦一列に整列して表示される
```

## テストケースに含める事項

- 前提条件・テスト環境（ブラウザ、OS、解像度）を明記する
- 期待結果を検証可能な形で記述する

## テスト結果の記録

- テスト実施結果（合否、スクリーンショット等のエビデンス）を対象タスク（issue またはタスクファイル）に記録する
- スクリーンショットの取得には `screenshot` skill を利用できる
