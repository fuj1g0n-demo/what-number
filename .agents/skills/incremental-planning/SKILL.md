# インクリメンタルな実装と統合

AI を活用した開発において **検証可能な小さな範囲で実装を完結させ、その都度確実に検証を終わらせる** ことで、
品質と手戻りリスクを管理するアプローチ。

## 基本方針

- ユーザーストーリーの実装は **小さく独立した増分（インクリメント）** に分割し、それぞれを個別に実装・統合・検証できる単位のサブタスクとする
- 各インクリメントは **単独で動作確認・テスト可能** な状態とし、実装のたびに検証を完了させる
- 大きな機能を一度に実装して検証が困難になることを避け、段階的に積み上げることで、各段階での品質確認を確実に行う

## 分割の手順

1. ユーザーストーリーの Acceptance Criteria を分析し、段階的に実装・統合・検証できる単位に分割する
2. 各インクリメントは以下の条件を満たすこと:
   - **単独でビルド・テストが通る**こと（既存機能を壊さない）
   - **そのインクリメント単体で動作確認が可能**であること
   - **前のインクリメントの成果物の上に積み重ねられる**こと（依存関係の順序を考慮）
3. 分割の粒度は「1 つの PR で完結し、レビュー可能なサイズ」を目安とする

## 各インクリメントのサブタスクに含める内容

- 実装順序（どのインクリメントの後に着手するか）
- 詳細設計の概要
- テスト計画:
  - Unit Test の対象範囲
  - Integration Test の対象範囲
  - System Test の対象範囲（テストケースは Gherkin 形式で記述）
- そのインクリメントで検証可能になる Acceptance Criteria の項目

テストレベルの詳細（技術スタック・ソースセット・実行コマンド）は `testing-strategy` skill を参照すること。
